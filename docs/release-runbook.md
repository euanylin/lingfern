## Rollback and recovery are different operations

| Failure | Permitted recovery after specific approval | Required proof |
|---|---|---|
| Bad frontend/Worker | Restore the captured prior compatible Worker+asset deployment using verified installed Wrangler rollback/version commands | Previous version exists and is tested; assets/catalogue/headers and revoked grants remain correct |
| Incompatible schema | Stop affected remote writes; use a reviewed forward-compatible fix, or separately approved isolated recovery plan | Preserve authoritative sessions/revocations; code rollback does not undo D1 |
| Missing content/old chunk | Restore exact approved immutable bytes/catalogue; preserve local answers | Hashes match supported snapshots and old browser can reopen safely |
| Key loss/rotation | Follow separate token/share key plan; keys never restored from project snapshots | No silent reactivation of expired/revoked shares/accounts; explicitly reauthorise if needed |
| Browser/profile fault | Export retained data, validate ZIP and restore into a new isolated profile by default | Original profile unchanged; exact submitted answers/snapshots/exposures and strict-device restrictions retained |
| Remote outage/quota | Keep pending batch IDs, stop bounded retry and show actionable state | Installed learning/answers/export continue; no public-repository or cloud fallback |
