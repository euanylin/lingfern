# Search metadata

Public search entries are defined in `src/shared/seo.ts` and `public/sitemap.xml`. The current five entries are Introduction, Dictionary, IPA, English usage and About. `/sitemap.xml` is the only sitemap endpoint and is declared in `robots.txt`; `/sitemap` returns404. The sitemap does not enumerate learner state or practice identifiers.

## HTML and navigation

Vite fills the single `<!--seo:start-->` / `<!--seo:end-->` block in the app shell. The Worker and cached Service Worker navigation replace that block and set the document's language/direction before client scripts run. Cached responses discard stale entity/length/encoding headers and retain the route's robots/cache policy without changing the cached template. `src/app/pageMetadata.ts` applies the same metadata using the selected interface language after client navigation, language changes and offline loading. Preserve both markers and keep unrelated head elements outside them.

Public pages use the concise English titles `Dictionary`, `IPA chart`, `Usage` and `About`, without a brand suffix, and have descriptions in all fourteen dedicated `src/locales/<locale>/seo.json` packages, including Open Graph and summary-card descriptions. Root and Introduction use the title `Lingfern` without a tagline. The 404 title uses its existing localized page name without a suffix. The existing512px installation icon supplies the social thumbnail. Root and Introduction share the Introduction canonical; only these entry pages supply truthful `WebSite` JSON-LD. The interface still follows the saved language setting. About's body remains English, with its own `lang="en" dir="ltr"`; its surrounding interface and metadata may be localized.

The maintainer chose the existing five public URLs, with English as the default when no supported request language is supplied. There are no additional language routes, query aliases, sitemap entries or invented `hreflang` targets. The Worker negotiates the supported `Accept-Language` preferences by quality and returns matching descriptions, root language/direction and public prerendered body. HTML responses use `Content-Language` and `Vary: Accept-Language`; existing public `no-cache` and personal `private, no-store` policies remain. Only the exact root `/` was added to `run_worker_first` so the home address can negotiate language too; static resource/protocol routing stays selective. Client changes use the selected profile language without adding another preference cookie.

This is locale-adaptive delivery, not fourteen separately indexed editions. Googlebot generally sends no `Accept-Language`, so it normally receives the default English version and may not crawl/index every language variant. Snippets are chosen by the search engine from page content and metadata. The implementation does not guarantee a particular snippet, multilingual indexing or ranking. See [Google's locale-adaptive guidance](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages) and [snippet guidance](https://developers.google.com/search/docs/appearance/snippet).

Personal pages use `noindex, follow` with no canonical or private `og:url`. Lookup URLs with a `q` parameter also use `noindex`, retaining their public base canonical. Tracking parameters are removed from canonical URLs. No query text, profile names or practice IDs enter metadata. Protocol responses use `X-Robots-Tag: noindex, nofollow`; authentication and authorization remain unchanged. No new robots.txt crawl block prevents crawlers from reading these directives. Indexing directives are not access controls.

Known HTML routes accept ordinary HTML, XHTML and generic crawler requests. Explicit JSON-only requests and unknown routes keep real errors. Metadata rendering strips stale entity/length/encoding headers and conditional/range requests to the small underlying shell; private document responses are not publicly cached.

## Verification and release

- Focused checks: `npm exec -- vitest run tests/seo.test.ts`; browser cases in `tests/browser/seo.spec.ts` and `routes.spec.ts` use the compiled8787 preview.
- Build once with `npm run build`. Deployment checks require that the local HTML template matches its sealed manifest hash, derive each route's exact expected bytes from that template, and retain version pinning, all-file checks and recovery guards. A title change is not accepted merely because the response is HTML.
- For a new public page, align the route, public metadata map, sitemap and corresponding regression; do not automatically index stateful pages.

Canonical public paths also contain the existing initial page body. `scripts/prerender.ts` uses Vite's server module loader and the existing React components at build time; `src/prerender.tsx` loads their actual modules and language package before rendering. Shared grammar/IPA input files are read once each per build. Seventy internal language templates serve the same five public paths. Bootstrap prepares the template's language before hydration, retaining the server body even when saved preferences differ. It then applies the saved language, theme and profile through the existing local-data loader. Profile-writing controls stay disabled until that loader is ready.

Grammar and IPA receive their validated public data in the document, avoiding a second initial JSON request. Existing disclosure behavior remains: closed grammar explanations are rendered when opened. No learner database is read while producing public documents. The root `/` retains its existing profile-dependent introduction/start/Today routing; query variants and personal routes retain the empty client shell. They do not receive a public bootstrap snapshot.

Static style properties are emitted as a small same-origin stylesheet, then restored through CSSOM before hydration. No inline-script/style permission is added to CSP. Identical generated CSS is shared across language variants through one content-hashed URL. Internal `/prerender/*.html.txt` and `/prerender/<locale>/*.html.txt` objects avoid Static Assets' automatic HTML redirects; only canonical page routes return them as HTML. These helper objects are marked noindex and excluded from the sitemap. They are excluded from SW precaching because offline navigation already uses the ordinary cached shell, with the same language-aware metadata renderer.

No crawler-specific body, telemetry, artificial rating, fake date or Search Console token is supplied. Search Console/Bing verification, submission and live crawl inspection require the deployed site and authorized account access. This local configuration does not claim indexing or rich-result acceptance.
