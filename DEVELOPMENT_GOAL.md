# Development continuation

This is a reusable navigation prompt, not an active task or standing publication instruction. The former first-launch objective is complete; its acceptance record (local evidence: `docs/history/2026-10-26-first-public-launch.md`) owns that decision.

When explicitly asked to continue development:

1. Read [AGENTS.md](AGENTS.md) and [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md).
2. Read the single current [handoff](DEVELOPMENT_HANDOFF.md), [implementation summary](IMPLEMENTATION_STATUS.md) and [issue list](Issues.md).
3. Inspect actual code, workspace changes and configuration; select the next concrete item within the user's request. Do not restart completed provider/device acceptance or replay historical operations.
4. Finish the smallest complete change and applicable local verification. Preserve current functionality, source attribution, security, offline recovery and learner data.
5. Publish only when requested, following local testing → guarded Cloudflare acceptance → identical-source GitHub synchronization without GitHub CI. Keep workflows disabled and retain exact source/resource/protection guards.

A focused request finishes at that scope. Historical session names, temporary paths and old release packets are evidence only, not commands or renewed authorization.
